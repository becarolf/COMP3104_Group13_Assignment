DevOps in the Software Development Life Cycle (SDLC)

The software development life cycle describes the work involved in planning, designing, building, testing, releasing,
and maintaining an application. DevOps practices connect these stages through shared responsibility, automation, and feedback.

During planning and design, development and operations teams can agree on requirements, reliability goals, and how the
software will be supported. During development, Git records code changes and helps teammates work together. Continuous
 integration can build and test each change so defects are found earlier.

During release and deployment, automated pipelines make delivery steps repeatable. After release, monitoring and user
feedback help the team detect problems and decide what to improve. Those findings can inform the next planning cycle.

These practices can reduce manual errors, shorten feedback loops, and make releases more predictable. They also make it
 easier for teams to respond to problems and continue improving software after it is deployed.

Security Throughout the SDLC
Security in the Software Development Life Cycle (SDLC) means making security a priority at every stage of development,
from planning and gathering requirements to testing, deployment, and maintenance. By identifying potential threats
early, using automated security checks, and continuously monitoring systems, teams can catch vulnerabilities before they
reach production. This approach allows developers to work efficiently while meeting security standards and regulations.
It also gives organizations a clearer understanding of security risks and helps ensure that every software release meets
their security requirements.

Example: Using Monitoring Feedback to Improve the Next Development Cycle
Imagine a team releases a new feature and notices that the application is running slower than usual. By looking at
performance data and user feedback, the team can identify the problem and make it a priority in the next development
cycle. Developers can then reproduce the issue, figure out what is causing it, and make the necessary improvements. They
can also add tests to help prevent the same problem from happening again. Before releasing the fix, Continuous
Integration (CI) runs automated tests to make sure everything works properly. After deployment, the team continues
monitoring the application's performance to check whether the issue has been resolved. The results can then help the
team plan future improvements.
